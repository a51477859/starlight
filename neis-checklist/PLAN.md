# 1학기말 나이스 가이드 — 계획 v2

> v1(메모지 보드 하나)은 종이 체크리스트와 다를 게 없었음. v2는 **“1학기말 나이스 작업 전체를 안내하는 사이트”**이고, 메모지 보드는 그 안의 진행 현황 화면 하나.

## 0. 이 사이트가 종이보다 나은 이유 (한 줄씩)

1. **헷갈리는 것에 바로 답한다** — “교과학습발달상황 고치려면 어디서?” 같은 질문을 찾아보면, 고칠 곳 · 그다음 다시 눌러야 할 것까지 나온다
2. **순서를 지켜 준다** — 앞 단계가 끝나야 다음이 열리고, 앞을 고치면 학생부 · 통지표 반영이 자동으로 다시 열린다
3. **나이스 화면을 그대로 보여 준다** — 실제 화면을 다시 그려서, 어디를 누르는지 커서로 따라간다
4. **우리 반 것만 남긴다** — 학년 · 전입생 · 동아리 · 학교 방침에 맞게 할 일이 줄어든다
5. **문장을 점검해 준다** — 바이트, 기재 금지, 특수문자, (1학기) 표기

## 2. 사이트 구조

왼쪽 사이드바(데스크톱) / 위쪽 가로 메뉴(모바일), 해시 라우팅, 한 폴더 오프라인.

```
지금 할 일          ← 첫 화면
우리 반 설정
전체 흐름
단계별 가이드        ① 기초 ② 출결 ③ 기록 입력 ④ 성적 ⑤ 반영·검증 ⑥ 통지표 (+정정대장)
  └ 업무 페이지 ×13 (할 일 · 나이스에서 보기 · 헷갈리는 점 · 기재 원칙)
이럴 땐 어디서?      ← 헷갈리는 것 모음 + 수정 길찾기
진행 현황(메모지)    ← 그룹 다 하면 떼기, 완료한 작업 목록
문장 점검
바뀐 점 · 출처
```

### 2-1. 지금 할 일 (첫 화면)
- 맨 위: 6단계 진행선(① 기초 → ⑥ 통지표). 현재 단계 강조, 끝난 단계 체크
- 가운데 큰 카드 하나: **지금 할 일** — 할 일 이름, 나이스 경로, 버튼 순서, [나이스에서 보기], [다 했어요]
- 그 아래: 이 일에서 자주 헷갈리는 것 2~3개(펼침)
- 옆: 다음에 할 일 3개 미리보기, 학교 마감일까지 D-day(설정한 경우)
- **다시 반영 알림**: 앞 단계를 고쳐서 반영이 풀린 경우 맨 위에 “학생부 → 통지표 다시 반영” 띠

### 2-2. 우리 반 설정 (처음 한 번, 나중에 수정 가능)
- 학년(1~6) → 학폭 메뉴 사용 여부(1~3학년)
- 전입생 있음 / 없음 → 전입생 할 일(이전학교 종합의견, 이전출결자료, 학교자율시간)
- 동아리 담당 여부, 자율동아리 · 청소년단체 · 스포츠클럽 운영
- 학교 방침(학성위): 누가기록 사용, 행특 학기 구분, 통지표 나이스 활용, 학부모서비스 반영 여부, 질병미인정·지각 사유 입력 기준
- 학교 마감일(선택): 출결 마감, 성적 입력, 통지표 배부
- 결과: “52개 중 우리 반은 31개” 같이 줄어든 수를 보여 줌

### 2-3. 전체 흐름 — 자료가 어디서 어디로 가는지
- **자료 흐름 지도(인터랙티브 다이어그램)**: 입력 메뉴(원본) → 학생부 반영 → 통지표 반영
  - 예: 교과평가 · 관찰내용 → 학기말종합의견(원본) → 교과학습발달상황(일괄저장 복사) → 학생부 → 통지표
  - 예: 동아리 학생부자료기록 → {동아리특기사항가져오기} → 창체 학생부자료기록 → 학생부
  - 칸을 누르면 “여기를 고치면 다시 눌러야 하는 것”이 길로 표시됨
- 왜 이 순서인지 짧은 설명(연수자료 흐름도 기반)

### 2-4. 단계별 가이드 — 업무 페이지 (13개)
한 페이지 구성:
1. 제목 · 경로 · 누가 입력하나(담임/전담/동아리 담당)
2. 할 일 체크(우리 반 설정에 맞게 걸러짐, 체크는 모든 화면에서 동기화)
3. **나이스에서 보기** — 시나리오 재생(아래 4절)
4. **헷갈리는 점** — Q&A 카드
5. 기재 원칙 · 예시 · 금지(기재요령 발췌, 쪽수)
6. 다음 할 일로 이동

### 2-5. 이럴 땐 어디서? (핵심)
- **수정 길찾기**: “무엇을 고치고 싶나요?” 선택(교과학습발달상황 / 학기말종합의견 / 창체 특기사항 / 동아리 / 행동특성 / 출결 / 인적사항 / 담임이력 / 통지표 문구…) → 답:
  1. 원본은 어디(메뉴 경로)
  2. 고친 뒤 순서대로 다시 할 것(예: 학기말종합의견 수정 → 교과학습발달상황 {일괄저장} → 학생부 {전체반영} → 통지표 {전체반영} → {반별마감} 확인)
  3. 이미 마감했다면(통지표 마감취소, 정정대장 필요 여부)
  4. 해당 나이스 화면 바로 보기
- **헷갈리는 것 모음**: 30~50개 Q&A, 주제 필터 + 검색(`/` 키). 예
  - 통지표에 고친 내용이 안 나와요 / 동아리 특기사항이 학생부에 안 보여요
  - 1학기에 학생부를 마감하나요? / 비고와 출결특기사항 차이
  - 전입생 학기말종합의견이 비어 있어요 / 학부모서비스 반영 버튼은 언제
  - 자율동아리 30자(90바이트) / 스포츠클럽 ‘(00시간)’ 표기 / 개근은 언제

### 2-6. 진행 현황 (메모지 보드)
- v1 보드를 다듬어 유지: 그룹 메모지, 그룹 다 하면 귀퉁이 떼기, 완료한 작업 목록
- 단계 순서대로 정렬, 잠긴 단계는 흐리게 + 이유
- 가독성 수정: 글자 면은 회전 · 필터 없음, 본문 16px, 글자색 거의 검정(대비 7:1 이상), 회전은 떼는 동작에만

### 2-7. 문장 점검
- 붙여 넣으면: 바이트(한글 3 · 영문 · 숫자 · 공백 · 엔터 1), 항목별 한도(자율동아리 30자, 출결 특기사항 500자, 봉사 50자)
- 기재 금지 후보 표시: 대회 · 수상 · 어학시험 · 자격증 · 대학명/기관명/상호명 · 장학금 · 부모 직업
- 특수문자 · 문단 번호 기호 · 명사형 종결 아닌 문장 · 행특 ‘(1학기)’ 누락 · 출결 ‘사유(n일)’ 형식
- 결과는 “확인해 보세요”(판정이 아니라 안내) — 문장은 밖으로 보내지 않음(브라우저 안에서만)

## 3. 순서 · 연결 모델 (데이터)

```js
{ id, stage, group, text, path, buttons, who, cond /*설정 조건*/,
  requires: [...]/*먼저 끝나야 할 것*/,
  reflects: 'record' | 'report' /*반영 단계 항목*/,
  sources: ['연 p.97', '기 p.104'], faq: [...] }
```
- 잠금: `requires`가 다 끝나야 열림(강제는 아님 — ‘그래도 하기’ 가능)
- 재반영: 입력 항목을 체크 해제 또는 “고쳤어요” → 그 뒤의 `reflects` 항목 자동 해제 + 알림
- 저장: localStorage(체크 · 설정 · 뗀 시각), 내보내기/가져오기(JSON 파일)로 다른 컴퓨터 이동

## 4. 나이스 화면 따라하기 — 이 사이트의 핵심

> 강의 교안(picturebook)처럼 **실제 화면을 재구성한 화면이 실제처럼 동작**해야 한다. 그림 위에 화살표가 아니라, 메뉴가 열리고 · 조회하면 그리드가 채워지고 · 팝업이 뜨고 · 저장하면 확인창이 뜨는 진짜 같은 나이스.

- **두 가지 모드**
  - **보기**: 가짜 커서가 실제 순서대로 움직이며 누르고, 단계마다 설명이 바뀜(교안의 tour 방식). 이전/다음 · 자동 재생 · ←/→
  - **직접 해 보기**: 선생님이 직접 누름. 다음에 누를 곳만 은은히 강조하고, 다른 곳을 누르면 “여기가 아니라 ○○예요” 힌트. 끝까지 하면 그 할 일이 체크됨
- **실제처럼 동작하는 것**: 0단계 메뉴 → 메가메뉴 열림 → 트리 펼침 · 선택 → 아래 탭바에 화면 탭 추가 · 전환 / 조회조건 셀렉트 변경 → {조회} 시 로딩 → 그리드 채움 / 행 선택 · 체크박스 · 전체선택 / 셀에 글자 입력(바이트 카운터 증가) / 팝업(제목줄, 라디오, 과목 셀렉트) / “저장하시겠습니까?” 확인창 → 저장 완료 / 스텝박스 단계 이동 / ‘확인필요’ 빨간 링크 → 오류 내용 / 마감 상태 바뀜
- **상태가 이어짐**: 한 시나리오 안에서 앞에서 입력한 학기말종합의견이 일괄저장 팝업에 그대로 나오고, 학생부반영 일시 그리드에 반영 시각이 찍히는 식으로 화면끼리 연결

- **HTML/CSS로 다시 그림**(이미지 아님): 확대해도 선명, 문구 수정 쉬움, 개인정보 없음(가상 학교 · 교사 · 학생)
- 부품: 상단바 · 0단계 메뉴 · 메가메뉴 · 아이콘 레일 · 트리 · 제목줄 · 스텝박스 · 하위 탭 · 조회조건 · 그리드(체크/링크/바이트 열) · 버튼(파랑/남색) · 팝업 · 확인창 · 아래 탭바 — 색과 크기는 `_source/RESEARCH-*.md` 측정값
- 시나리오(JSON): `goto`(메뉴 열기) · `click` · `hl`(강조 링) · `popup` · `type` · `check` · `toast` · `zoom` + 단계 설명 문장. 왼쪽 단계 목록과 동기화, 이전/다음 · 자동 재생 · 키보드 ←/→
- 축소 화면: 패널 폭에 맞춰 1440×900 화면을 비율 축소, 누를 곳 근처 자동 확대
- 우선순위 시나리오(헷갈림 많은 순)
  1. 교과학습발달상황 {일괄저장}(과목별 · 1학기 체크) 
  2. 학기말종합의견 수정 → 재반영 길
  3. 학생부반영 {전체반영} → 자료검증 {전체검증} → ‘확인필요’ 예외처리
  4. 생활통지표 자료반영 및 마감관리 {전체반영} → {반별마감}
  5. 출결 일일출결 {마감} → 출결특기사항등록
  6. 창체 학생부자료기록 {동아리특기사항가져오기} → {저장}
  7. 행동특성 학생부자료기록 / 누가기록 {행추가}
  8. 전입생 이전학교 학기말종합의견 {가져오기}
  9. 학급시간표 시수편차 확인
  10. 기본신상 · 학년반이력 {등록}
  11. 정정대장 1~4단계

## 5. 디자인

- 기준선: jaehee-archive(먹색 머리줄, Pretendard, tabular 숫자, 사이드바) 이상
- **가독성 우선**: 본문 16px / 줄간 1.65, 보조 14px 이하 금지(라벨 제외), 글자색 #1E2024, 회색 글자도 4.5:1 이상

- 메모지 모티프는 ‘지금 할 일’ 카드와 진행 현황에만
- unslop 검수(60항목) 단계마다 통과: 이모지 · 느낌표 · 그라데이션 · 글로우 없음, 굵기 400/500, transform/opacity 모션, reduced-motion, 다크 모드
- 인쇄: 우리 반 설정이 반영된 A4 체크리스트

### 에셋
- 나이스 화면, 아이콘, 다이어그램은 코드(HTML/SVG)로 — 가장 정확
- 생성 이미지는 필요할 때만(Codex 등으로 선생님이 뽑아 주실 수 있음): ① 첫 화면 빈 상태 삽화 “교무실 책상 위 메모지” ② 완료 화면 삽화 ③ 단계 아이콘 6종(선택). 프롬프트는 제작 때 따로 정리
